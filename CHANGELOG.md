# Changelog

fsp-mint 0.1.2 builds on `sp-wire` 0.2.0 (wire version 2) and mint-core 0.1.3. Nothing was recorded per version before this file; the section below is everything the README said about what was built and when.

## 0.6.0 (2026-10-22): sp-wire v0.5.0 and esp-mint v0.7.0 from GitHub

**Builds from GitHub with no local patch.** `Cargo.toml` names `sp-wire` at tag `v0.5.0` (it named `v0.4.0`, which has no `air-client`) and the dev-dependency `esp-mint` at tag `v0.7.0` (it named `v0.5.0`, which has no `air_listener` or `EspState::open`), and the committed `Cargo.lock` follows. sp-wire 0.5.0 pins AIR at `eae5133` (3.0.0 plus the `SecretKey` export) and air_server at `v1.0.1`, which takes `air` from crates.io, so `Cargo.toml` adds `[patch.crates-io] air` at that AIR commit; the commented local patches for AIR and air_server are gone, and the README's "Building" says this. No code change. Tests: 66, unchanged.

## 0.6.0 (unreleased)

- **Changed: mint-core `v0.2.0`, and the unused `mint-server` dependency is gone.** mint-core's `server` crate no longer exists (nothing ran its `mintd`); fsp-mint declared it and never used it. Pins: mint-core, mint-types and bdhke `v0.2.0` (from `v0.1.3`); sp-wire stays at `v0.5.0`. No source change. The dev-dependency esp-mint `v0.7.0` must be tagged on mint-core `v0.2.0` and sp-wire `v0.5.1`.

**The calls to the ESP mint, and the wallets' calls to this mint, go over AIR, and only over AIR.** Builds on `sp-wire` with the `air-client` feature (a build needs the local AIR patches, see the README, "Building"); `Cargo.toml` still names `sp-wire` and the `esp-mint` test dependency by their old tags.

- **Behaviour change: caps on the size ceiling, the item counts, the memo and the fee rate, checked when the settings load (regtest round 1, ROADMAP item 18).** `server.max_request_bytes` is 16,384 to 15,728,640 bytes (was 4,096 to 1 GiB; 15 MiB is the most one AIR message carries), `issue.max_items` and `spend.max_items` 64 to 25,000 (were 1 to 100,000), `spend.max_memo_bytes` 0 to 1,024 (was 0 to 65,536) and `fees.issue_fee_per_byte` 0 to 30,000,000 (was 0 to 10^12), so that no rate makes a one-note issue group cost more than a 1 PSP note. Defaults are unchanged and the fee stays 0. A settings file outside a range now stops the mint at start, naming the setting, the value and the range. The numbers are worked in DESIGN.md, "Caps on sizes and fees".
- Tests: 5 added in `config.rs`, one for each cap. Two existing tests use values inside the new ranges: `the_note_limits_come_from_the_settings` sets items of 100 and 200 where it set 50 and 20, and `a_body_over_the_ceiling_is_refused_before_parsing` (`tests/fsp_flow.rs`) uses a ceiling of 16,384 where it used 4,096; the config load-error test looks for `16384` where it looked for `4096`.
- **Behaviour change: a spend with spent inputs is refused `note_spent_elsewhere` with every spent position in `spent` (regtest round 1, ROADMAP item 18).** It answered `already_spent` with the first position in the text. An issue naming ESP notes already transferred to this service gets the same code and `spent` (positions counted across the groups in order); it answered `already_spent` with no position. `SpendError` and `IssueError` have a `spent` field (empty for every other refusal). The wallet reads the code, so a spent FSP note now leaves its balance and the rest are freed instead of the rollover being sent again on every connection.
- Tests: 2 added, `two_spent_notes_not_at_the_start_are_both_named_and_nothing_else_is_spent` (a spend, positions 1 and 2) and `two_transferred_esp_notes_not_at_the_start_are_both_named` (an issue, positions 1 and 2 across two groups), both in `tests/fsp_flow.rs`. Three expectations change from `already_spent` to `note_spent_elsewhere` with the `spent` list (`one_spent_note_among_several_leaves_the_others_unspent` and the two checks in `issue_mixed_days_keeps_the_esp_and_never_issues_twice`).
- **Behaviour change: HTTP to the ESP mint is removed.** `HttpIssuer` and the ESP HTTP client are deleted, `reqwest` is now a dev-dependency (the tests call the HTTP API of this mint). The three calls (the network check at `serve`, the current keyset, the ESP transfer of an issue) are mint info, keysets and transfer requests sealed to the ESP mint's DID (`esp_air::AirIssuer`, sp-wire's `ask`). No cargo feature: AIR is always built in. A reply maps as before: answered is `Done`; a signed refusal with the `400` body is `Refused` with its code and text; a `409`, a `5xx`, "cannot answer now" and no reply after the tries are `Unknown`, so the issue stays `502` and pending.
- **Behaviour change: new settings, required by `serve`.** `air.esp_did` (`FSP_AIR_ESP_DID`), `air.esp_server` (`FSP_AIR_ESP_SERVER`) and `air.esp_host` (`FSP_AIR_ESP_HOST`) for the calls to the ESP mint, and `air.server` (`FSP_AIR_SERVER`) and `air.host` (`FSP_AIR_HOST`) for this mint's own listener, are required and `serve` names any that is missing; there is no built-in DID. (`air.server` and `air.host` were the ESP's server in the first 0.6.0 work; they were renamed `air.esp_server` and `air.esp_host` before release, so nothing reads the old meaning.) `air.held_reads` (`FSP_AIR_HELD_READS`, default 16, 1 to 200) is the listener's. Each pair is marked as **to be replaced by DID resolution**. Also `air.reply_wait_secs` (30), `air.attempts` (3), `air.max_skew_secs` (300) and `air.timeout_secs` (10), with `FSP_AIR_*` variables, checked when set.
- **Behaviour change: `esp.url` and `esp.timeout_secs` are removed** (and `FSP_ESP_URL`, `FSP_ESP_TIMEOUT_SECS`). A file or an environment that names them is refused with a message that says they are gone and what replaces them. `esp.keyset_ttl_secs` is kept: it is how long the ESP mint's keyset, now read over AIR, is cached.
- **The request in flight is kept in `issues.json`, in the pending group of the transfer it carries** (`air`: request id, one-off key, slots, ESP mint DID, transfer hash, time). A retry reads the reply cell first and writes no second request. Files written before 0.6.0 have no `air` and read as none in flight.
- **Behaviour change: wallets reach fsp-mint over AIR only; `POST /issue`, `POST /spend`, `GET /keys`, `GET /fees` and `GET /rotation` are gone from HTTP.** fsp-mint has its own AIR listener (`src/air_listener.rs`, always running under `serve`, under the service's DID: requests are sealed to `service.did`, replies signed by `service_key.hex`; no new key), shaped like psp-mint's and esp-mint's. The calls are AIR kinds: mint info 1, keys 2, rotation 4, fees 7 and two new in `sp-wire`, **FSP issue 11** and **FSP spend 12**. The reply body is the route's exact JSON, size ceilings are unchanged, a `400` is a signed refusal with the route's JSON, any other `4xx` a refusal with `"http_status": N`, a `5xx` (the `502` of an ESP mint that does not answer included) a signed "cannot answer now", so the issue stays pending and the retry gets the stored answer. The handlers' logic is unchanged: each route became an outcome function (`keys_outcome`, `issue_outcome`, ...), shared by `server::air_served`; about 200 lines of axum handler code (extractors, body limits, `Json` plumbing) are gone.
- **`GET /audit` and `GET /health` stay on `server.bind`, which must now be loopback** (a non-loopback address is refused when the settings load, as in psp-mint and esp-mint). `/audit` is the operator's. `/health` stays because the local health monitor polls it (`ops/env/fsp-mint-health.conf.example`), as it does esp-mint's: the brief said to stop and report before removing a route something local calls, so it is kept and named in the report. `serve` prints the wallet's `air.fsp` entry, `<service DID>@<AIR server key>@<host>`, when the listener is up.
- **Version 0.6.0** (the file said 0.5.0, which is not released).
- Tests (the HTTP tests moved onto AIR, none dropped): the HTTP router in `tests/fsp_flow.rs` is replaced by fsp-mint's real AIR listener on the same real `air_server` as esp-mint's, with the helpers shared in `tests/common/mod.rs` (a client that reads a reply as the route's status and JSON, so the assertions stayed the same); each test uses its own service key, because a service's mailboxes on the shared server are its DID's. New: an issue and a spend end to end, a refused spend (a `400` with the route's JSON, nothing spent), an ESP mint that does not answer (the wallet's issue stays pending as a signed "cannot answer now", the retry finishes it with no second issue), `serve` refusing without each of its five AIR settings, a non-loopback `server.bind` refused, and only `/audit` and `/health` answering over HTTP (the old routes are 404). The earlier note follows: `tests/fsp_flow.rs` now runs esp-mint's real AIR listener on a real `air_server` (`local_server`, one test at a time) and fsp-mint's `AirIssuer` in every test, so the existing issue, refused-group, rotation, spend and audit tests exercise the ESP over AIR. New: the network and keyset read over AIR; an ESP mint that stops answering (the issue stays pending with its request kept, a restart and a retry finish it with one transfer and no second request); a network mismatch stops `serve`; `serve` refuses to start without the AIR settings, and a config that names `esp.url` is refused. Unit tests: the settings and the removed ones (`config.rs`), a kept request and its hash (`esp_air.rs`), the request handed back to the retry and an old file (`issue.rs`). No test was deleted: none exercised the ESP over HTTP except through `start_esp`, which is now the AIR listener. `ecash-wallet`'s `tests/fsp_flow.rs` and `tests/handoff_flow.rs` build fsp-mint with `HttpIssuer` and `esp.url`: they need a change there.

- **Behaviour change: the "not counted" path is removed.** Nothing was released before the counters, so there is no data folder without them. `IssueData.uncounted_requests`, `IssueData::start_counting`, `Counters.uncounted_spends`, `Report.complete` and the two warnings that went with them are gone; the `audit --json` report and `GET /audit` no longer have `complete`. A spend-log line must have its amounts (`a`); a line without them no longer reads as "uncounted" and is a damaged log.
- **The `Issuer` trait is smaller.** `transfer` is removed; `transfer_kept` and `network` are required (the only real Issuer, `AirIssuer`, already defined both). The test stand-ins implement them.
- **`Spender::is_spent` is `#[doc(hidden)]`.** Only tests call it; the comment says so.
- **Behaviour change: a data folder that cannot be read says where.** The first read of the data folder, in `main` before any command runs, now fails with `cannot read the data in <folder>: ...`, as `audit` already did, instead of a bare `Not a directory (os error 20)`. `keysets::parse_date` (no caller since 0.1.0) is removed.
- **`export-esp` moved to `src/export.rs`** as `fsp_mint::export::export_esp(data_dir, out, service, now)`, and `main` calls it and prints what it printed before. It writes the shared `sp_wire::esp::handover::Handover`, not hand-built JSON. The file has the same fields; **its keys are no longer sorted**: they come in the order of the type (service, day, notes; amount, note, spend secret, keyset), and `Handover::read` does not depend on the order. **Behaviour change:** a kept note with an empty keyset (kept before keysets) stops the export before anything is written, with a message that names the note, instead of writing `"keyset": ""` (`Handover::read` refuses such a file).
- Tests: the ESP fixture is the mint `esp-mint serve` builds (`EspState::open`, rotation on), and the ESP the tests issue is booked in its ledger as an exchange books it. Cut: `what_was_answered_before_the_counters_is_reported_as_not_counted`, `a_pending_group_without_a_kept_request_reads_as_none_and_is_written_without_one`, `every_keyset_field_is_in_the_issue_and_spend_request_hashes` (it tested sp-wire's hashes, which sp-wire's own tests cover) and `throughput_of_the_spend_path` (a speed measure, not a check). Merged into the `serve` tests that run the real program: the two config tests of the AIR settings and of the loopback bind. Tightened: the kept-request tests read `issues.json` back as `IssueData` and compare `PendingGroup.air`; two bare `is_err()` checks now match the error. Added: `tests/cli.rs` (an unknown command and the usage, a damaged or unknown setting, `export-esp` without `--out` or `service.did`, an audit that cannot read the data, and a file where the data folder should be) and tests of `export_esp` (the hand-over files read back with `Handover::read`, a second run writing nothing, the refusal of a note with no keyset). `fsp_run` and `scratch` moved to `tests/common`.

## 0.5.0 (unreleased)

**Wire version 3: the service ID is the 33-byte AIR DID.** Builds on `sp-wire` 0.5.0 (`WIRE_VERSION` 3) and mint-core 0.1.3; `Cargo.toml` still names `sp-wire` and the `esp-mint` test dependency by their old tags, which move when the new releases are tagged (until then the tests run against local copies, see the README of `sp-wire`). No migration and no dual format.

- **`service.did` (`FSP_SERVICE_DID`) is the DID: 66 hex characters starting `02` or `03`.** The 32-byte x-only form is refused when the config loads, with a message that says to use the DID. `Config::service()` returns an `sp_wire::ServiceDid`.
- **`fsp-mint service-key` prints the DID** (the key's compressed public key), and the startup check compares the whole DID with `service_key.hex`, the parity byte included: a `service.did` that differs from the key's only in `02` and `03` stops the mint with "They must match".
- **The service in `GET /keys`, `POST /issue`, the transfer to the Issuer and `export-esp` is the 66-character DID.** A request naming another DID (a different parity counts) is `wrong_service`. The transfer to esp-mint is still signed with BIP340 and checked there against the x-only half.
- `storage.mint_state` takes DIDs, not x-only keys.
- **Files written by 0.4.0 that hold a service** (a pending entry in `issues.json`) **do not load.** There is nothing to migrate: start with a clean data folder.
- Tests: the config checks (a DID is valid, the x-only form is refused, an uppercase DID is lowercased), the storage setting, `issue.rs` and `tests/fsp_flow.rs` use the DID of the service key.

## 0.4.0 (2026-10-17)

- Test helpers take `&Path` instead of `&PathBuf` (lint). Documentation: the storage requirements are the numbered set (1 to 8), and the service files and health monitor are described by the SPI repository, not by a folder outside this repo. Every fee setting defaults to 0 (`fees.issue_fee_per_byte` is the only one), stated in the README.
- **Operator audit.** `GET /audit` and `fsp-mint audit [--json]`: outstanding FSP per key set and in total (`issued + change - spent`, in FSP units and PSP), FSP expired with deleted key sets, and the ESP in reserve from the kept list, matured and unmatured, in ESP and PSP, with a line per redeemable-after day and the part already written out by `export-esp`. `complete` and `consistent` flags and warnings.
- **Crash-safe counters.** `issues.json` gets `issued` (FSP units per key set, saved with the stored answer) and `uncounted_requests`; each spend log line gets `a` (input and output units); `ledger.json` (new) keeps the counters of deleted key sets, copied before their logs go and repaired at start-up from logs left behind. Old data still loads: lines and answers from 0.3.0 are reported as not counted.
- The spend log reader has a read-only mode that ignores a half-written last line instead of cutting it (used by `audit`; `serve` still cuts it at start-up).
- New module `audit`. Tests in `tests/fsp_flow.rs`: counts across issue (once, with a retry), spend, change and a refused spend; the reserve across the maturity day; rotation, expiry, the report from the files equal to the report from the mint, and a restart; a key set deleted before its counters were saved; a torn last line read without cutting; data from 0.3.0.
- No dollar figure: the payout rate is not kept in this repo. `spi audit` does that arithmetic and leaves FSP out.

## 0.3.0 (2026-10-17)

- **Setting `storage.mint_state` (`FSP_STORAGE_MINT_STATE`): which AIR services will keep this mint's state.** An ordered list of service IDs (index 0 the primary, the rest secondaries); one entry is valid, empty (the default) means local only, at most 8, no duplicates. Config and validation only: nothing reads or writes the AIR, the state is still local files. The parser and checks are `sp_wire::storage` (sp-wire 0.4.0), shared with the other mints and the wallet. In `fsp-mint.toml` the value is an array of strings or one string. DESIGN.md has "Storage policy (setting only)"; the planned behaviour is in sandbox-mint's DESIGN.md, "AIR storage requirements".
- `sp-wire` is now the `v0.4.0` tag. Tests: the setting from the file and the environment, both forms, and every kind of refusal.

## 0.2.1 (2026-10-16)

- Tests: `tests/fsp_flow.rs` builds esp-mint's state with the new `in_flight` field, so it needs esp-mint after the lock change (the local folder, or the next tag). `sandbox-mint/scripts/test-wallet-against-local-mints.sh` now also runs fsp-mint's tests against the local esp-mint.

- **Running as a service.** `serve` now stops on SIGTERM as well as SIGINT (the API drains and the process exits 0); before, it did not stop gracefully on either. `tokio` gets the `signal` feature. `launchd` and `systemd` definitions, env and monitor settings examples and `sp-health-monitor.sh` are in `sandbox-mint/ops`, with the steps in `sandbox-mint/OPERATIONS.md`. DESIGN.md: "Running as a service", with what the AIR storage has to keep.

## 0.2.0

- The cache of the ESP mint's current keyset is no longer refreshed when the ESP mint answers `keyset_not_current` (it no longer sends it: it signs with any live keyset). It is still dropped and read again on `keyset_retired`.
- **The spend memo limit is a setting.** `spend.max_memo_bytes` (`FSP_SPEND_MAX_MEMO_BYTES`, default 256, the old constant) is the longest memo on a spend, and is served on `GET /fees` as `spend_max_memo_bytes` (a new optional field of `sp-wire`'s `FeesResponse`: a mint that does not send it is read as the default). Tests: the default and the range; a memo over the limit gets `memo_too_long` and spends nothing; `GET /fees` serves it.
- The comment at the top of `keysets.rs` described rotation by `activation_date` and `period_days`; it now describes the hours the code uses.
